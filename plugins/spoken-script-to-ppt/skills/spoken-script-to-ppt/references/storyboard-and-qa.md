# 页面蓝图、口播同步与验收

## 1. 中间产物

默认在临时目录保存以下 `.txt` 文件，不作为用户交付物：

```text
script-map.txt
message-spine.txt
slide-blueprint.txt
visual-prompts.txt
source-notes.txt
qa-ledger.txt
```

若用户只要拆解或视觉分镜，可把相应内容直接呈现或另存为用户要求的格式。

## 2. 页面蓝图字段

每页使用以下字段：

```text
slide_id: S01
source_paragraph_ids: P01-P03
cue_in: 原稿中触发本页的短语
cue_out: 原稿中离开本页的短语
slide_role: cover | hook | problem | thesis | evidence | comparison | mechanism | steps | case | summary | action
audience_shift: 看完本页后听众认知发生什么变化
message_headline: 与页面角色匹配的结论、问题或行动标题
visible_copy: 页面上真实出现的全部文字
visible_text_count: 标题 / 叙事正文 / 节点与标签的字数
narration_delta: 由口播补充、刻意不写在页面上的信息
visual_type: photo | screenshot | illustration | chart | diagram | icons | typography
visual_brief: 主体、动作/关系、构图、画风、文字安全区
asset_or_data_need: 来源、授权、生成、数据或核验需求
layout: 主视觉、文字和辅助元素的位置与比例
speaker_notes: 对应原稿范围、翻页提示和来源
```

`slide_role` 只是可选角色集合，不要求每份 PPT 具备全部角色。

## 3. 口播同步规则

- 页面顺序跟随原稿信息第一次出现的顺序。
- `cue_in` 和 `cue_out` 优先使用原稿中简短且唯一的锚点。封面和结尾可用 `START` / `END`；重复短语使用“短语 + 第 N 次出现”；用户另附已对齐音频/视频时可补充经核验的时间码。
- 页面只展示口播已经引出的信息，不提前泄露后续反转、答案或 CTA。
- 同一页面可以覆盖多段对同一观点的解释；只有认知任务改变时才翻页。
- 默认使用能在最终静态渲染中完整理解的页面。只有现场演示确实需要、制作路线能可靠实现且每个动画状态都能预览验收时，才使用逐步揭示；否则不要依赖动画，也不要复制成多张几乎相同的页面。
- 最终 PPTX 必须写入 speaker notes；若当前制作路线不能嵌入 notes，改用支持 notes 的路线，不得以单独临时文件代替后仍宣称通过来源门。使用以下结构：

```text
[Script]
对应原稿原文或准确范围

[Advance cue]
cue_in / cue_out

[Narration delta]
本页由口播补充的内容

[Sources]
- claim: URL 或用户提供的来源
- asset: URL、访问日期和授权/引用说明
```

## 4. 逐页内容门

每页必须同时满足：

- 一个主要结论或认知任务；
- 屏显内容可追溯到原稿或明确外部来源；
- 观点、证据和对比页用结论式标题；封面极简，钩子可用问题，步骤/行动页可用动词式标题。任何角色都不能只写“背景、问题、解决方案”等空栏目名；
- 无逐字稿段落；`visible_text_count` 已按页型记录并通过预算，`message_headline` 没有在 `visible_copy` 中被近义重复；
- 口播中被省略上屏的解释已记录在 `narration_delta`；
- 不改变原文的确定性、因果、范围、主体或时间；
- 不提前泄露后续口播。

## 5. 逐页视觉门

- 普通内容页有一个承担语义的主视觉；刻意留白的大字页可例外。
- 主视觉通常占主内容区 65%–85%，不是角落里的装饰图。
- 图片、图表、图解、图标或重点文字与本页任务匹配。
- 不重复使用同一主图；没有无意义图库图、低清图、水印或不自然裁切。
- 真实证据没有被 AI 生成或漫画化到失真。
- 图表关系、数字、比例、单位、基线和来源准确。
- 插画、照片处理、图标、人物、配色、线条和颗粒保持全套一致。
- 图片内无生成式文字；可编辑文字和图表保持清晰。

## 6. 全稿口播协同门

- 静音快速浏览能看懂整场演讲的主线，但 PPT 不会变成完整报告。
- 只听口播时内容仍然完整，PPT 不是理解基本信息的唯一来源。
- 两者同时使用时，PPT 提供证据、关系、结构或形象记忆，而不是同步字幕。
- 所有不可缺失的核心论点、关键证据、步骤、限制和 CTA 已覆盖。
- 相同观点没有重复屏显；连续页面的版式和视觉类型有节奏变化。
- 页序与口播顺序一致，翻页锚点自然。

## 7. 来源门

- 用户提供的原稿是内容来源，但不自动证明其中外部事实已核验。
- 外部事实、数据、照片、截图、Logo 和图标都有可追溯来源记录。
- 关键事实会随时间变化时使用实时一手来源核验。
- 原稿中出现重要但无来源的数据或事实时，按以下顺序处理：
  1. 能核验且不改变原意：补一手来源。
  2. 无法核验、但只是非关键经历或观点：明确归因于用户原稿/匿名案例，使用定性或条件化表达，不制作精确图表。
  3. 无法核验且是中心论证所必需的事实或数字：向用户索要来源，或请求授权将其改为可核验/定性版本；获得决定前不得交付为已证实结论。
  4. 与可靠来源直接冲突：不得静默修正或照抄，报告冲突并请用户决定修改口播还是删除/归因该说法。
  5. 医疗、法律、财务、安全等高风险关键主张无法核验时，阻止最终交付，不用视觉包装掩盖风险。
- AI 生成插画标记为解释性素材，不把它列作事实证据。
- `Presentations` skill 要求的 `[Sources]` 区块存在且与页面资产对应。

## 8. 技术门

按照 `Presentations` skill 完成全部技术检查：

1. 渲染每一页。
2. 逐页全尺寸检查，不只看缩略图。
3. 联系表检查整套节奏、色彩、人物和版式一致性。
4. 修复所有非预期重叠、溢出、裁切、断行、错误连接线、占位符和低清素材。
5. 确认标题没有意外换行，图表与来源一致，图片在投影尺寸下清晰。
6. 使用动画时逐一预览并检查每个构建状态、出现顺序和 cue；无法验证时改为静态页面。
7. 修订后重新渲染受影响页面；重大风格变更后重新检查全稿。

## 9. 失败模式与修正

| 失败 | 修正动作 |
|---|---|
| 原稿逐段复制进页面 | 重新执行内容分类，只保留结论、精确数字和标签 |
| 一段原稿一页 | 按认知任务合并或拆分 |
| 标题只是栏目名 | 改成听众应该记住的判断句 |
| 字少但信息也少 | 让主视觉编码具体关系、动作或证据 |
| 每页都是“人物拿电脑” | 视觉 brief 写出具体冲突、动作、场景或隐喻 |
| 没数据却画柱状图 | 改用定性对比、连续场景或关系图 |
| 为漫画风扭曲案例照片 | 保留真实照片，只统一边框、色板和注释语言 |
| 图片风格各不相同 | 统一风格锁，整组复审并替换跳脱素材 |
| 图片内直接生成标题 | 使用无文字图片，标题由 PPT 文本叠加 |
| emoji 或多图标库混用 | 换成一个成熟 SVG 图标家族 |
| 页面像仪表盘或卡片墙 | 回到一个主画面、一个主层级的平面构图 |
| PPT 比口播提前讲完 | 检查 `cue_in`、`cue_out` 和 `narration_delta` |
| 只看联系表就交付 | 必须逐页全尺寸渲染检查 |

## 10. 交付判定

只有内容门、视觉门、口播协同门、来源门和技术门全部通过后才能交付最终 PPTX。默认不交付临时地图、蓝图、提示词和 QA 记录，除非用户明确要求。
