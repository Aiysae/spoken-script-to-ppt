# 视觉路由与画风规则

## 1. 先判断信息关系，再选择视觉

每页只选择一种主视觉，必要时加一种辅助视觉。

| 信息关系 | 首选视觉 |
|---|---|
| 真实人物、企业、产品、地点、事件、案例 | 真实照片、产品截图、现场图 |
| 抽象概念、情绪、隐喻、无法拍摄的机制 | 编辑漫画或商业插画 |
| 有可靠数字的趋势、比较、构成、分布 | 正确的数据图表或重点数字 |
| 没有数字的比较 | A/B 插画或并列场景，不能伪装成图表 |
| 流程、时间、因果、层级 | 流程图、时间线、因果链或连续场景 |
| 3–5 个类别、功能或要点 | 同一家族的成熟矢量图标或物体插画 |
| 核心观点、金句、结论 | 大字重点文字 + 一个辅助主视觉 |
| 前后变化 | Before/After 分屏 |

选择顺序：

1. 有可靠数据时优先图表。
2. 有明确流程、关系或层级时优先可编辑图解。
3. 具体人物、产品、地点或证据优先真实照片或截图。
4. 抽象概念、情绪和不可拍摄场景使用插画。
5. 并列分类使用成熟矢量图标。
6. 强结论可直接用重点文字，不为“有图”硬加无意义配图。

普通页上限：一个认知任务、一个主视觉、零到一个辅助视觉、一条标题、零到三个短标签。步骤、分层、分类和流程页可有 3–5 个必要节点，按 [content-distillation.md](content-distillation.md) 的页型预算执行。

## 2. 真实照片和截图

- 具体人物、品牌、产品和事件必须使用真实素材，不能用 AI 生成图冒充证据。
- 素材优先级：用户已确认有权使用的素材 > 使用条款覆盖目标用途的官方素材 > 授权明确的图库 > 许可或引用条件覆盖目标用途的公开素材。官方素材、Logo 和截图仍可能受版权、商标或品牌规范限制，不能因“来自官网”就默认可自由再分发。
- 产品截图、界面和 Logo 不进行漫画化重绘。
- 不使用握手、会议室指白板、假笑客服、泛化电脑办公等空洞图库套路。
- 搜索“动作或关系”，而不是只搜索主题名。例如需要表达“流程卡住”，搜索真实受阻或拥堵场景，而不是普通办公室。
- 记录 URL、访问日期、授权/引用依据和对应页面。
- 一致裁切比例、色温和对比度；轻微色彩蒙层可以统一画面，但不得影响证据真实性。

## 3. 编辑漫画与商业插画

适合抽象概念、比喻、机制、情绪和虚构故事。默认风格锁：

```text
现代编辑漫画 / 商业插画；清晰轮廓；轻微纸张或半调颗粒；
有限而统一的色板；一个明确视觉焦点；背景简洁；人物比例自然；
适合演示文稿远距离观看；画面中不生成文字、数字、商标、水印或界面；
按页面文字位置预留安全区域。
```

规则：

- 一幅画只表达一个动作、冲突或关系，3 秒内能看懂。
- 不把一句话中的所有名词都塞进画面。
- 同一人物跨页出现时，发型、服装、年龄、体型、肤色和配色保持一致。
- 避免默认变成儿童卡通、复杂日漫、廉价 3D 或写实 CG，除非用户明确要求。
- 图片不含文字和数据；标题、标签和数字在 PPT 内原生排版。

常用隐喻仅作为起点，不能机械套用：

- 选择：岔路、两扇门、分叉箭头
- 增长：台阶、攀登、向上路径
- 瓶颈：漏斗、拥堵、狭窄出口
- 风险：冰山、裂缝、警戒线
- 因果：多米诺骨牌、涟漪、链条
- 信息过载：堆积文件、拥挤屏幕
- 认知差：隔墙、不同高度的平台
- 转型：桥梁、换轨、破壳
- 聚焦：聚光灯、靶心、放大镜

## 4. 图表

只在原稿或可靠来源提供真实数据时使用。

| 关系 | 图表 |
|---|---|
| 时间趋势 | 折线图 |
| 类别大小比较 | 横向条形图或点图 |
| 占比 | 100% 堆叠图；类别不超过 3 个时可用环形图 |
| 分布 | 直方图或箱线图 |
| 两变量关系 | 散点图 |
| 阶段变化 | 时间线或阶梯图 |

硬规则：

- 不编造数字；没有数据时改用定性图解。
- 不使用 3D 图表、仪表盘装饰、立体饼图、假坐标轴或图标数量伪装比例。
- 只高亮支持本页结论的一组数据，其余使用中性色。
- 坐标、比例、单位、时间范围和基线准确，不截断或夸大。
- 采用直接标签，减少图例查找。
- 漫画感只能体现在配色、圆角、手绘圈注或强调箭头，不能改变数据几何关系。

## 5. 流程、机制和关系图

- 节点控制在 3–5 个。原始关系有 6 个以上节点时，先归并成 3–5 个阶段或拆成多页，不通过缩小节点和文字强塞。
- 节点名称使用“动词 + 对象”，不写长句。
- 默认从左到右；时间较长使用横向时间线；循环机制使用闭环。
- 关系箭头必须明确，装饰线不能与关系线混淆。
- 简单关系用可编辑的 PPT 原生图形；复杂网络按 `Presentations` skill 的路由实现。
- 只有当图解确实比照片或插画更清楚时才使用，避免整套 PPT 变成流程图合集。

## 6. 图标

- 整套 PPT 只使用一个图标家族，如 Phosphor、Lucide 或 Material Symbols。
- 优先可编辑 SVG；同页保持相同线宽、圆角、填充和视觉重量。
- 官方品牌 Logo 使用官方文件和规范颜色。
- 图标适合表达分类和功能，不适合承担复杂观点。
- 禁止 emoji、Unicode 字符、AI 伪图标、临时几何图形或多套图标库混搭。

## 7. 双层视觉体系

用“纪实内容 + 编辑插画语言”统一真实照片与漫画画风：

- 真实照片、截图、Logo 负责可信度和事实。
- 插画、箭头、框线、标签、图表和图标负责解释。
- 照片可放入统一的漫画分镜框、圆角容器或不规则描边，配合统一的手绘箭头、圈注、贴纸标签和轻微半调颗粒。
- 不把证据照片强行转成卡通；不影响人物身份、产品细节、界面文字或数据可读性。
- 禁止同时混用写实 3D、黏土、日漫、水彩、照片拼贴等多套画风。

开始找图前定义“视觉基因”：

```text
primary_color
accent_color
neutral_colors (2–3)
background_tone
headline_font / body_font
corner_radius
line_weight
shadow_direction
grain_level
photo_treatment
icon_family
recurring_character_reference
```

## 8. 版式与节奏

默认视觉占主内容区 65%–85%，文字占 15%–35%。优先版式：

- 封面：满版主视觉 + 6–12 字标题
- 核心观点：大图 2/3 + 大字结论 1/3
- 案例：真实照片/截图 + 一个结论标签
- 对比：左右分屏
- 流程：3–5 个横向步骤
- 数据：单图表 + 单一突出数字
- 分类：3–5 个同风格图标
- 收束：大字结论 + 一个象征性插画

连续两页尽量不要使用完全相同的版式。只有两种视觉路线同样准确时，才优先在照片、插画、图解/图表之间形成节奏变化；语义适配和证据真实性始终高于机械交替。重要结论前后可以使用留白更多的页面。内容装不下时拆页或重写，不缩小字号。

## 9. 搜索和生成提示

搜索关键词结构：

```text
具体主体 + 明确行为 + 使用场景 + 镜头类型 + 横版 + 授权要求
```

插画生成提示结构：

```text
表达目的
主体与明确动作/关系
视觉隐喻
场景与情绪
横向构图和主体位置
标题安全区位置
宽高比与裁切
统一风格锁
禁止文字、数字、Logo、水印、复杂背景、多余人物、多余肢体和边缘裁断
```

根据最终版式生成或搜索素材，提前指定文字位于左侧还是右侧，不依赖后期强行裁切。

## 10. 视觉验收

- 3 秒测试：第一眼能否说出本页大意？
- 相关性测试：图片是否解释观点，而不是只做装饰？
- 单焦点测试：是否只有一个明确视觉中心？
- 一致性测试：配色、线条、人物、图标和照片处理是否统一？
- 数据测试：数字、单位、比例和来源是否准确？
- 可读性测试：缩略图或投影状态下重点是否清晰？
- 可编辑测试：图表、流程、文字是否保持可编辑且无生成式错字？
